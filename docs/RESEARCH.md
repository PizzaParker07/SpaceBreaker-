# Research, dungeons & guide — how other areas plug in

Everything here is server authoritative; clients get a synced copy of the known technologies.

## Technologies
- Tree data: `data/<ns>/spacebreaker/tech/<id>.json` (`core/tech/TechNode`). The built-in tree is defined in
  `content/research/ResearchTree.java` (names + descriptions in English and Turkish) and written by `./gradlew runData`.
  Data packs may add or override nodes. Fields: `category`, `tier`, `requires`, `icon`, `unlocks`,
  optional `research_time` (ticks), `energy` (FE/t) and `samples` (sample kinds that can reveal it).
- Names: language keys `tech.<ns>.<path>` and `tech.<ns>.<path>.desc`.
- Branches: the six built-in ones are propulsion, life_support, industry, astronomy, construction, exploration. A new
  branch (e.g. for the outer system) is just a new `category` string: the research screen gives it its own row after
  the built-in ones; add the language key `tech_category.spacebreaker.<category>`.
- `unlocks` must only name registered items, blocks, entities or recipes (a GameTest checks this); leave it empty for
  technologies whose content does not exist yet.
- Sample kinds are celestial body ids; a sample kit on Titan gives `spacebreaker:titan` samples. Kinds already used by
  technologies: earth, moon, mars, venus, mercury, phobos, ceres, vesta, io, europa, ganymede, callisto, titan,
  enceladus, meteorite, suborbital_flight, orbital_flight.
- Query / change: `Tech.knows(player, id)`, `Tech.learn(player, id)`, `Tech.all(registryAccess)`,
  `Research.teach(serverPlayer, id, shareWithTeam)`. Every change posts `TechChangedEvent` (sync, toast, advancements).

## Gating your content (`core/tech/TechRequirement`)
```java
// explicit
TechRequirement req = TechRequirement.of(Spacebreaker.id("liquid_fuel_engines"));
if (!req.check(player)) return InteractionResult.FAIL;      // creative passes, others get an action-bar message
// strict (no creative bypass), e.g. for the rocket assembler validating a design
boolean ok = req.test(player);
// in your own JSON (recipes, fabricator jobs, rocket parts): "tech": "spacebreaker:x" or ["a:x", "b:y"]
TechRequirement fromJson = TechRequirement.CODEC.parse(JsonOps.INSTANCE, json.get("tech")).getOrThrow();

// data-driven: list your item / recipe / feature id in a technology's "unlocks" array, then
TechRequirement.isUnlocked(player, Spacebreaker.id("rocket_assembler"));  // false until a tech that unlocks it is known
TechRequirement.canUse(player, stack);                                     // same for an item stack (creative passes)
```
Ids nobody lists in `unlocks` are always unlocked. The research area does not gate anything inside other areas'
code: call these where your machine, recipe or item decides.

## Samples and experiment records
`Research.sample(Spacebreaker.id("moon"))` (field sample) and `Research.experimentData(Spacebreaker.id("orbital_flight"))`
make the items. A technology lists the kinds it reacts to in `samples`. The sample kit uses the celestial body id of
the current dimension. Kinds already used: `earth`, `moon`, `mars`, `venus`, `meteorite`, `suborbital_flight`,
`orbital_flight` (add `sample.<ns>.<kind>` translations for new ones). Rocketry can hand out experiment records after
flights; probes after fly-bys.

## Milestones (advancements)
`Milestones.award(serverPlayer, Milestones.FIRST_ROCKET | LAUNCH | ORBIT | MOON_LANDING | SAFE_RETURN)`.
Entering `spacebreaker:earth_orbit` / `spacebreaker:moon` also completes orbit / Moon landing.

## Dungeons (`content/dungeons`)
1. Worldgen structure + template pool + structure set + biome tag; templates are generated by code
   (`tools/structures/modules/<area>.py`, run `python3 tools/structures/gen_structures.py`).
2. Chests use loot tables `spacebreaker:dungeons/<world>/<name>`; roll disks with
   `{"function": "spacebreaker:random_tech_disk", "categories": [...], "max_tier": 2, "samples": ["spacebreaker:moon"]}`
   on an entry of `spacebreaker:tech_disk` (or a fixed one with `"techs": [...]`).
3. `data/<ns>/spacebreaker/dungeon/<name>.json` (`DungeonDef`): structure id, world, guardians. Players entering it get
   the `spacebreaker:dungeon_discovered` advancement trigger (filters `dungeon`, `world`) and a "Discovered" message;
   guardians spawn once per generated site.
4. Java behaviour: `DungeonHooks.onFirstDiscovery(id, ...)` / `DungeonHooks.onEnter(id, ...)`.
5. Name: language key `dungeon.<ns>.<name>`. Add your structure to the tag `#spacebreaker:dungeons`.

## Field guide
The guide is a two-page book (`client/guide/GuideScreen.java`) built from Markdown, one file per chapter and language:

- `assets/<ns>/guide/book.json`: categories (`id`, `color`, `icon`, `chapters`) and the `machines` map (recipe type → machine
  item shown on recipe arrows). Files of every namespace are merged, so another mod can add categories or chapters.
- `assets/<ns>/guide/<lang>/book.json`: book title and category names.
- `assets/<ns>/guide/<lang>/<chapter>.md`: the chapter. English is the fallback for a missing language.

Front matter: `title`, `icon`, `items: [..]` (clicking these items anywhere in the book opens the chapter) and an optional
`research: <tech>`, which only shows a "Research needed" note: pages are never hidden.

Body (see `GuideMarkdown.java`): `#`/`##` headings, `-` and `1.` lists, `**bold**`, `*italic*`, `` `code` ``,
`{color gold}…{/color}` or `{blue}…{/}`, tables, `---` dividers, `>` tip and `>!` warning boxes (also `> [!TIP]`, `> [!WARNING]`,
`> [!NOTE]`), `## Heading {#anchor}`, links `[label](chapter)`, `(chapter#anchor)`, `(#anchor)` and `(https://…)` (asks first), and the tags
`{item id [text]}`, `{key key.name}` (the player's real key), `{tech id}`, `{page}`, `{recipe id}` (crafting, cooking,
smithing and every Spacebreaker machine, fluids and gases included), `{items id id ...}`, `{entity id}` (turning model),
`{structure id}` (turning 3D view of the multiblock `data/<ns>/spacebreaker/multiblock/<id>.json`, with a "Show hologram" button for the Hologram Projector; `assets/<ns>/guide/structures/<id>.nbt` is the fallback for scenes that are not multiblocks)
`{entity id scale=1.5 height=50}`, `{craft shaped a b c / d _ f -> result x2}` and `{image ns:textures/... w h}`.
A `?` after a tag name (`{recipe? id}`) skips it quietly while the target does not exist yet.
The language `book.json` also takes `subtitle` and `intro` for the contents page.

The GameTest `guideChaptersExistInBothLanguagesAndResolve` checks that every chapter exists in English and Turkish and that
every item, recipe, entity, structure, link, tech, image and key it names exists. Terms: `docs/GLOSSARY.md`.
