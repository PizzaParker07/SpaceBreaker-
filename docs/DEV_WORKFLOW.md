# Spacebreaker — Development workflow

## Rules (always)
- **Commits** are authored as the project owner, with descriptive messages and nothing else:
  `git -c user.name=PizzaParker07 -c user.email=104515967+PizzaParker07@users.noreply.github.com commit`.
  No `Co-Authored-By` lines, no links, no tool or assistant names — in commits, code, comments, docs or assets.
- Credits are only "PizzaParker07 / Pizzacı Çocuk".
- Never commit secrets, tokens or personal e-mail addresses.
- No copyrighted names, characters, art or music from other games/films/mods. No blood.
- Textures are drawn by code (`tools/textures`); models/blockstates are generated by `tools/models`.
- Languages: English (`en_us`) and Turkish (`tr_tr`) — every string in both, via `Lang` in the module.
- Heavy jobs (game client, server, test runs) one at a time per machine.

## Project layout
```
src/main/java/com/pizzaparker07/spacebreaker/
  Spacebreaker.java          mod entry; registers core + every module in core/module/Modules.ALL
  core/                      shared APIs — change only when needed, keep backwards compatible
    module/                  SbModule interface + Modules list
    body/                    CelestialBody data model + data-pack registry (Bodies)
    env/                     Environment: gravity, air, pressure, temperature, radiation, sunlight
    tech/                    research tree registry + per-player known tech
    config/                  server + client config
    lang/, data/, SbTabs     translations, loot/tag sinks, creative tabs
  content/<module>/          one package per feature area (earth, moon, machines, suit, rocketry, ...)
  client/<module>/           client-only code for that area
src/main/resources/data/spacebreaker/spacebreaker/celestial_body/   body data (real units)
src/testmod/                 GameTests + automated showcase (never shipped)
tools/textures/modules/      one texture script per area, with export(save)
tools/models/modules/        one model script per area, with generate()
```

## Adding a module
1. `content/<name>/<Name>Module.java` implementing `SbModule` (own DeferredRegisters, lang, loot, tags).
2. One line in `core/module/Modules.ALL`.
3. `tools/textures/modules/<name>.py` and `tools/models/modules/<name>.py`.
4. GameTests in `src/testmod/.../testmod/<name>/` and a showcase scenario.
Avoid editing other modules' files; if you need something from another module, use its public fields or add
a small API in `core/`.

## Build and test
```
python3 tools/textures/generate.py && python3 tools/models/gen_assets.py
./gradlew runData                  # lang, loot, tags
./gradlew build                    # jar
./gradlew runGameTestServer        # all GameTests must pass
LIBGL_ALWAYS_SOFTWARE=1 xvfb-run -a -s "-screen 0 1920x1080x24" ./gradlew runShowcase -Pscenario=<name>
# with Sodium + Iris + shader pack: put jars in run-mods/, the pack in run-showcase/shaderpacks/,
# iris.properties in run-showcase/config/, then add -PwithCompat=true -PshotPrefix=iris
# -Pshots=<regex> takes only matching shots; renderer checks: -Pscenario=compat (see docs/COMPAT.md)
# recipe viewers: -Pscenario=jei -PwithJei=true, -Pscenario=emi -PwithEmi=true (JEI/EMI on the run classpath only)
```
Screenshots land in `run-showcase/screenshots/`. Copy the best ones (as compressed JPG, ≤ 400 KB each)
to `docs/screenshots/<area>/` when a content pack is ready for review.

## Definition of done (per feature)
- Builds, all GameTests pass (new feature has its own tests), showcase screenshots reviewed (vanilla + shaders),
  `en_us` and `tr_tr` complete, `docs/CONTENT.md` updated, follows `docs/STYLE.md`.

## Work areas (parallel development)
Each area is developed on its own `dev/<area>` branch and merged into `1.21.1` by the integrator.
Merge `origin/1.21.1` into your branch regularly. Only edit the paths you own; `core/` changes must be
small, additive and explained in the commit message.

| Area | Branch | Owns |
